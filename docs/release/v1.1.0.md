# iqdb-filter v1.1.0

Caps on the total size of a filter.

## Security

- **Total size is bounded.** `FilterEvaluator::new` already capped nesting
  depth (64) and the width of each `In` (1024), but not how many children an
  `And` or `Or` could hold. Every child is evaluated for every record, so a
  single filter of wide `In` nodes could cost on the order of 10^8
  comparisons per record and pin a core for hours on a modest corpus.
  Validation now also rejects a filter with more than **4096 nodes** or more
  than **16,384 `In` values** in total. The width of each `And` / `Or` is
  checked before its children are walked, so rejecting an oversized filter is
  cheap.

## Added

- **`MAX_FILTER_NODES`** and **`MAX_FILTER_VALUES`**, the two new caps, as
  `pub const` alongside `MAX_FILTER_DEPTH` and `MAX_IN_VALUES`.
- **`FilterEvaluator::try_from(&Filter)`** validates a borrowed filter and
  clones it only once it passes, so a filter that belongs to the caller (for
  example `SearchParams::filter`) is rejected without being copied first.

```rust
let evaluator = FilterEvaluator::try_from(&filter)?;
```

## Behaviour notes

- A filter above either new cap used to be accepted and now returns
  `IqdbError::InvalidFilter`. Both caps sit far above hand-written or
  generated queries.

## Upgrading

Change the version to `1.1`. Nothing else is needed.
